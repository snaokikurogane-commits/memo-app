# V9 会話メモの入力・保存改善（2026-10-10）

## 変更

- 会話メモ、短いまとめ、次に聞くこと、次回目安、会話タグを人物別の下書きとして保持。
- 同じタブで入力を閉じても、再読み込みしても、同じ人物の入力画面から再開できる。既存の会話の編集下書きと、新しい会話の下書きは別々に保持。
- 下書きは `sessionStorage` に保持する。端末間・別タブ間の同期やバックアップの対象ではない。タブを閉じると失われる。ログアウト時にも削除する。
- ブラウザの保存領域を使えない場合はメモリ内で保持し、再読み込みでは失われることを画面に表示。
- 保存する会話と質問の識別番号を送信前に固定。再試行時は同じ番号を使い、既存行を変更せず不足分を追加する。送信後は各番号を読み取り、保存結果を確認。
- 途中失敗時は入力内容を保持して「保存を再試行」を表示。一部だけ保存された場合でも、保存済みの会話を重複して追加しない。結果確認中は内容を固定する。
- 保存後の一覧更新だけが失敗した場合は「保存は完了しました」と案内し、保存済みの下書きを残さない。
- 「下書きを破棄」は下書きだけを削除する。途中でデータベースに保存された会話や質問は削除しない旨を確認画面に表示。
- 質問は1行1000文字以内、会話メモは5000文字以内を保存前に確認。

## 仕組みと制限

- 下書きキーは接続先・アカウント・人物・編集対象を区別する。ログアウト前の通信が遅れて完了しても、再ログイン後の新しい下書きを変更しない。
- 会話と質問は別々のデータベース要求。途中まで保存される可能性は残るが、固定した番号と `upsert(ignoreDuplicates: true)`、読み取り確認で再試行する。
- 下書きは暗号化バックアップではなく、同じブラウザ内の一時的な保持。写真や人物情報の保存方式、既存の `.pnb` バックアップ形式は変更しない。
- ブラウザ保存が使えない場合、通信失敗後にタブを閉じたり再読み込みすると再試行用の番号も失われる。画面で再読み込みを控えるよう案内する。
- iPhone実機でのキーボード動作は未確認。375px / 320px の画面幅、入力欄16pxの文字サイズをブラウザで確認する。

## 確認方法

- Node の回帰テスト：途中失敗、会話・質問それぞれの応答喪失、連打、保存中の閉じ直し、一覧更新失敗、別人物・別アカウント・編集対象別の下書き、再読み込み、保存領域の利用失敗、ログアウト後の遅い応答、質問のみの保存、既存会話の編集。
- ローカルの架空データで、下書き復元と質問保存失敗からの再試行を画面操作で確認。実データへのテスト書き込みは行わない。
- データベースの構造変更は不要。保管済みSQLバックアップで両テーブルの主キーと文字数制限を確認。
- 最終実行：Node 76件、Python 6件すべて成功。架空データで375px / 320px幅に横方向のはみ出しがないことを確認。第三者コードレビューの重要指摘（ログアウト前の遅延通信による干渉）は回帰テストを追加して修正。
