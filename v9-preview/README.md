# 人物ネタ帳 V9 プレビュー

## 2026-10-29 入力画面と人物・趣味の表示

人物編集は、スクロールする入力欄と独立した保存欄へ分離しました。キーボードで表示位置が移動した場合も編集画面を追従させ、背後の一覧・詳細は表示・操作を止めます。通常の入力欄でEnterを押しただけでは保存せず、日本語変換の確定は妨げません。

人物一覧の左は写真または氏名の頭文字、名前の右には登録タグに対応する趣味アイコンを最大3件表示します。残りは件数で示し、人物詳細で全件と名称を確認できます。先頭の括弧や空白は頭文字に使いません。趣味の表示は表紙設定とは独立しており、保存済みの表紙・写真・タグを書き換えません。

趣味とタグ選択にはユーザー提供の最新50種の正方形素材を使い、従来の追加趣味も引き継ぎます。対応表は `interest-icons.js`。写真の読込失敗時は頭文字を表示します。アプリマークとmanifest・ホーム画面用画像は、今回提供されたうさぎの画像へ変更しています。既存のホーム画面アイコンはOS側で保持され、追加し直しが必要な場合があります。

通常テストに加え、PlaywrightとChromeがある環境で `node --test tests/browser/v9-usability.cjs` を実行できます。架空データだけを使い、320/390px・キーボード相当の表示移動・Enter/IME・趣味・タグ検索を確認します。編集中・保存中にログインが切れた場合も、編集画面とスクロール固定を解除し、古い保存処理が詳細を開き直さないことを確認します。iPhone実機のソフトキーボードは別途確認が必要です。

## 2026-10-28 会話をつなぐ入力

会話メモに「次回聞く」を付けると、同じ記録を次の話題として表示します。項目を開いて元の話を引用し、今回わかったことを保存して完了できます。続きにも次回チェックを付けられます。記録せず完了する場合は入力を空にし、保存前に閉じた場合は未完了のままです。

公開前に `20261028_013_conversation_links.sql` を適用します。引用と関連IDの任意項目、同一人物の検証、削除時の参照解除のみを追加し、既存のRLSや利用者権限は広げません。旧データは自動で関連付けません。引用はスナップショットとして保持し、元の記録がなくなっても文脈を確認できます。暗号化バックアップのv1/v2形式は継続し、新規の関連情報も保存・閲覧します。

保存は `conversation-flow.js` の処理と `conversation-store.js` のSupabase実装に分離しています。端末保存・同期は今回実装していません。通常入力、質問だけの入力、質問ごとの追記は別の下書きとして保持し、同じ保存IDによる再試行で重複を防ぎます。途中失敗の場合は完了を確認できるまで成功表示しません。

会話から作った次回項目の本文は読み取り専用の引用として残し、項目メニューからは次回目安だけを変更します。手動で追加した質問は従来どおり本文も編集できます。元の会話自体を編集しても、過去の引用はその時点の内容を保持します。

会話や次回項目を別の人物へ付け替える操作は提供していません。関連する記録の `person_id` を管理画面やAPIで直接変更しないでください。将来付け替え機能を追加する場合は、参照元からの整合性検証も先に追加します。

C案「趣味の絵と写真で見分ける人物手帳」。人物マークと登録済みの趣味を一覧・詳細で確認し、会う前に前回の会話と次の質問を確認できます。

## 画像の選択

- 既存人物は現在の15種類の表紙設定を維持します。新規人物は「趣味から自動」です。
- 自動表示は登録済みタグの順で、最初に一致した趣味を使います。対応表は `card-images.js`。AIによる判定や会話内容の推測はしません。
- 手動の趣味イラスト、表紙、写真はタグ変更で切り替わりません。
- 写真は端末内でJPEGへ変換し、長辺1600px・1MiB以下にします。HEIC/HEIFはブラウザの標準読込に対応している端末だけで利用できます。
- 編集画面の一覧用・表紙用プレビューで位置と拡大率を確認できます。写真は「保存する」までアップロードしません。

## Supabase設定

既存の人物・所属・会話・利用者権限の構造を維持し、`20261004_008_card_images.sql` を適用します。`people.card_image` を追加し、非公開 `person-card-photos` バケットを作ります。activeな利用者が閲覧し、owner/editorが追加・未使用写真整理を行います。既存人物の画像設定はnullです。

写真は `person_id/uuid.jpg` へ新規保存し、人物への書込成功後に未参照の旧写真を整理します。人物保存時は元の画像設定を条件にして、別画面で変更済みの画像を上書きしません。所属の保存に失敗した場合は、人物・画像の保存済み状態を案内して再試行できます。

## バックアップ

`.pnb` の中身はAES-GCMで暗号化されたJSON。外側の形式はv1、内側の人物データはv2です。7種類のテーブル、写真本体、表示位置・拡大率を含みます。パスワードからPBKDF2-SHA256（600,000回）で鍵を生成します。パスワードの送信や保存は行いません。

写真の取得・画像検証に失敗した場合は該当人物を示して中断します。暗号化ファイルの上限は100MiBで、これを超えた場合も成功と表示しません。`backup-reader.html` はv1/v2に対応し、復号・写真確認を端末内で行います。サーバーへの自動復元は行いません。管理者向け手順は `recovery.html`。

## 検証

`node --test tests/*.test.cjs`（リポジトリのルートから）。画像の選択、失敗時の旧写真保持、競合編集拒否、バックアップv1/v2、欠落・破損を確認します。`tests/fixtures/v9-supabase.js` は架空データを使うローカル検証専用で、公開アプリから読み込みません。

趣味イラスト40種と夕暮れシティを用意。従来の12種の制作記録は `assets/README.md`、追加28種は `assets/20261005-hobbies.md`。イラスト選択の検索欄では別名でも探せます。複数趣味は代表の絵を1枚表示します。iPhone実機でのHEIC読込・ソフトキーボード挙動は端末により異なるため、ブラウザ幅の検証とは別に確認が必要です。

40種の保存を有効にするには、008の後に `20261005_009_hobby_illustrations.sql` を適用します。この追加は保存済みの人物情報や写真のアクセス権限を変更しません。
