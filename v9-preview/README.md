# 人物ネタ帳 V9 プレビュー

C案「趣味の絵と写真で見分ける人物手帳」。一覧の左の絵と人物詳細の表紙を共通にし、会う前に前回の会話と次の質問を確認できます。

## 画像の選択

- 既存人物は現在の15種類の表紙設定を維持します。新規人物は「趣味から自動」です。
- 自動表示は登録済みタグの順で、最初に一致した趣味を使います。対応表は `card-images.js`。AIによる判定や会話内容の推測はしません。
- 手動の趣味イラスト、表紙、写真はタグ変更で切り替わりません。
- 写真は端末内でJPEGへ変換し、長辺1600px・1MiB以下にします。HEIC/HEIFはブラウザの標準読込に対応している端末だけで利用できます。
- 編集画面の一覧用・表紙用プレビューで位置と拡大率を確認できます。写真は「保存する」までアップロードしません。

## Supabase設定

既存の人物・所属・会話・利用者権限の構造を維持し、`20261004_008_card_images.sql` を適用します。`people.card_image` を追加し、非公開 `person-card-photos` バケットを作ります。activeな利用者が閲覧し、owner/editorが追加・未使用写真整理を行います。既存人物の画像設定はnullです。

写真は `person_id/uuid.jpg` へ新規保存し、人物への書込成功後に未参照の旧写真を整理します。人物保存時は元の画像設定を条件にして、別画面で変更済みの画像を上書きしません。所属の保存に失敗した場合は、人物・画像の保存済み状態を案内して再試行できます。

## バックアップ

`.pnb` の中身はAES-GCMで暗号化されたJSON。外側の形式はv1、内側の人物データはv2です。7種類のテーブル、写真本体、表示位置・拡大率を含みます。パスワードからPBKDF2-SHA256（600,000回）で鍵を生成します。パスワードの送信や保存は行いません。

写真の取得・画像検証に失敗した場合は該当人物を示して中断します。暗号化ファイルの上限は100MiBで、これを超えた場合も成功と表示しません。`backup-reader.html` はv1/v2に対応し、復号・写真確認を端末内で行います。サーバーへの自動復元は行いません。管理者向け手順は `recovery.html`。

## 検証

`node --test tests/*.test.cjs`（リポジトリのルートから）。画像の選択、失敗時の旧写真保持、競合編集拒否、バックアップv1/v2、欠落・破損を確認します。`tests/fixtures/v9-supabase.js` は架空データを使うローカル検証専用で、公開アプリから読み込みません。

趣味イラスト40種と夕暮れシティを用意。従来の12種の制作記録は `assets/README.md`、追加28種は `assets/20261005-hobbies.md`。イラスト選択の検索欄では別名でも探せます。複数趣味は代表の絵を1枚表示します。iPhone実機でのHEIC読込・ソフトキーボード挙動は端末により異なるため、ブラウザ幅の検証とは別に確認が必要です。

40種の保存を有効にするには、008の後に `20261005_009_hobby_illustrations.sql` を適用します。この追加は保存済みの人物情報や写真のアクセス権限を変更しません。
